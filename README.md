# O!Travel Agent — интеллектуальный конструктор путешествий

Проект команды **AegML** для трека «О!дин запрос» на хакатоне Островка.

Делаем агента, с которым можно собрать поездку в разговоре: выбрать маршрут, даты и отели, распределить людей по номерам. Если планы поменялись, агент должен пересчитать поездку и объяснить, что изменилось.

## Текущая версия

Есть backend, хранение поездок в PostgreSQL и React/JavaScript frontend Travel Studio: стартовый экран, чат, формы поездки, предложения отелей и перелётов, фотографии, сравнение изменений и тестовое оформление. Простой диагностический чат также сохранён.

После разбора 80 разговоров обновили денежные правки, маршруты, семьи, условия номеров и ответы по сохранённой поездке. Все проверки полного прогона прошли (7490), без падений и пропусков: [квитанция](docs/verification/prefrontend-r22-checkpoint-20261028.json). Это unit/Mock/API/PostgreSQL проверки, а не 7490 реальных диалогов. [Результаты языковых прогонов и открытые ограничения](docs/testing/AFTER80.md) учитываются отдельно.

Сейчас работаем над уточнениями, составными запросами и сохранением пожеланий при правках. В проекте уже есть:

- история изменений, пауза и продолжение разговора;
- несколько городов, группы взрослых и детей, распределение по номерам;
- демонстрационный поиск и адаптеры внешних источников;
- проверка корзины перед тестовым оформлением.

Бронирование и оплата пока имитируются. Данные демокаталога помечены в интерфейсе.

## Запуск

Нужен Docker с Compose. Ориентир для backend: 2 CPU, 4 ГБ свободной RAM и 2 ГБ на образы и данные; модель вызывается через API. Для первой сборки нужен доступ к публичным образам и пакетам.

```bash
git clone https://github.com/ostrovok-hackathon-2026/aegml.git
cd aegml
```

Демонстрационный режим запускается без ключей:

```bash
docker compose up --build
```

Travel Studio откроется на [localhost:8080](http://localhost:8080), диагностический чат — на [localhost:8080/debug](http://localhost:8080/debug), описание API — на [localhost:8080/docs](http://localhost:8080/docs). Прямой backend для разработки доступен на порту8081 (`BACKEND_PORT`).

База PostgreSQL и таблицы создаются при старте. В чате доступен готовый DEMO-пример. Без LLM-ключа свободный диалог ограничен: сохраняется поездка, доступны формы и готовые сценарии. Синтетические данные не выдаются за настоящую цену или бронь.

Чтобы подключить модель и внешние источники, скопируйте `.env.example` в локальный `.env` и заполните нужные поля. Все значения в примере пустые; значения по умолчанию заданы в Compose. В PowerShell файл можно скопировать командой `Copy-Item .env.example .env`, в Linux/macOS — `cp .env.example .env`. Если локальный порт8080 занят, задайте `APP_PORT=8081`; стандартный порт сдачи остаётся8080.

| Настройка | Default в Compose | Назначение |
| --- | --- | --- |
| `APP_PORT` | `8080` | Порт приложения на localhost |
| `LLM_PROVIDER` | `openrouter` | Явно выбранный провайдер модели |
| `DEFAULT_SEARCH_MODE` | `DEMO` | `HYBRID` включает настроенные туристические источники |
| `DEFAULT_HOTEL_PROVIDER` / `DEFAULT_FLIGHT_PROVIDER` | `liteapi` / `serpapi` | Источники новых поисков |
| `DYNAMIC_GEOGRAPHY_ENABLED` | `true` | Серверный справочник стран и городов |
| `MAX_LLM_CALLS_PER_DAY` / `MAX_LLM_CALLS_PER_RUN` | `40` / `2` | Ограничения приложения, не квота поставщика |
| `REFERENCE_FX_ENABLED` | `true` | Справочная конвертация с источником и датой курса |

Рабочий API-стенд отдельно проверял Groq `openai/gpt-oss-120b`; он выбирается через `LLM_PROVIDER=groq`, `GROQ_MODEL`, `GROQ_STRUCTURED_TRANSPORT_ENABLED=true`, `GROQ_TRANSPORT_VERSION=3`, `GROQ_REASONING_EFFORT=low` и подтверждённый Free-ключ. Точный набор для жюри фиксируется в отдельном зашифрованном env. Автоматического платного fallback нет.

LiteAPI и Duffel подключаются в SANDBOX, SerpApi даёт ориентировочные поисковые цены. У предложений отмечаются источник, время и валюта; перед тестовым оформлением выполняется перепроверка. Нет настоящих оплат или бронирований поставщика.

Проверка готовности — `GET /health`. API сессии требует собственного bearer-token; общих тестовых логина/пароля нет. Логи доступны через `docker compose logs app`. Данные PostgreSQL сохраняются в Docker volume между перезапусками.

## Сдача

Порядок подготовки ключей, финального тега и видео описан в [SUBMISSION.md](docs/SUBMISSION.md). Для LLM нужны отдельные ключи для жюри; основной ключ разработчика не передаётся. В Git допускается только зашифрованный `secrets.env.age`, открытый `.env` остаётся локальным.

Публичная ссылка на демо-видео пока не добавлена. Перед сдачей её нужно проверить в инкогнито. Финальный frontend готовится сокомандником отдельно; текущий `/debug` служит для проверки backend.

## Разработка

[React frontend: запуск, API и режимы](docs/FRONTEND_REACT.md). Исходники интерфейса — в `frontend/`; `npm ci` и `npm run dev` запускают его с proxy к backend.

Python, FastAPI, PostgreSQL, Docker Compose.

```bash
python -m pip install -c requirements.lock '.[dev]'
python -m pytest -q
```

Для интеграционных тестов нужна отдельная БД через `TEST_DATABASE_URL`. Тесты не должны работать с базой приложения.
