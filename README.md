# O!Travel Agent — интеллектуальный конструктор путешествий

Команда **AegML**, трек «О!дин запрос». Агент собирает сложную поездку и пересчитывает затронутые компоненты при изменении требований.

## Что уже работает

Backend на FastAPI и PostgreSQL, Docker Compose, версионное состояние поездки, типизированные правки, уточнения и явная пауза до команды «продолжай». Демокаталог поддерживает несколько городов, группы взрослых и детей, несколько номеров, бюджет и сравнение вариантов. Корзина перепроверяется перед **имитированным** заказом; версии и идемпотентность защищают от старых и повторных подтверждений.

Frontend разрабатывается отдельно участником команды. Здесь пока backend, Swagger и [контракт для frontend](docs/FRONTEND_CONTRACT.md). Корневой адрес возвращает JSON.

## Запуск

Нужен Docker Engine с Compose. В корне checkout:

```bash
cp .env.example .env
# Задайте свой POSTGRES_PASSWORD. Для демо API-ключи не нужны.
docker compose up --build -d
```

Открыть [Swagger](http://localhost:8080/docs) и [проверку состояния](http://localhost:8080/health). Если порт занят, задайте `APP_PORT=8081` в `.env`. PostgreSQL доступен только внутри Docker-сети; его данные остаются в volume `pgdata`.

Для локального проекта владельца выбран порт **8081**: существующий сервис на 8080 сохраняется. Docker и данные находятся в отдельной WSL-среде на NVMe C:. Подробности — [локальная среда](docs/LOCAL_SETUP.md).

## Модели и источники

- LLM подключается через адаптеры Gemini или OpenRouter. OpenRouter принимает только явно бесплатные `:free` модели и нулевые допустимые цены. Необязательный `OPENROUTER_BACKUP_MODEL` по умолчанию пуст; причины переключения и фактическая модель видны в аудите.
- При недоступной LLM поездка сохраняется. Формы, типизированные команды и демосценарии работают отдельно; свободное понимание текста без модели не обещается.
- Адаптеры: LiteAPI sandbox, Duffel test, SerpApi, Open-Meteo; опционально Hotelbeds test, RateHawk sandbox и справочные данные Travelpayouts. Наличие адаптера не доказывает доступ аккаунта или полноту маршрута.
- Каждый внешний компонент имеет происхождение и тип `DEMO`, `SANDBOX`, `LIVE_INDICATIVE` или `LIVE_BOOKABLE`. В этой версии подключение бронируемого live-поставщика ещё не подтверждено. Поисковая цена и sandbox не равны проверенной рыночной корзине.

Настройка ключей и ограничения — [API_SETUP.md](docs/API_SETUP.md). Ключи хранятся локально в ignored `.env`; в чат, Git и frontend их не передают. Реальное бронирование и платежи не выполняются.

## Проверки и границы

152 автоматических проверок прошли 25.10.2026: domain/inventory, адаптеры с MockTransport, PostgreSQL и HTTP/API. Сквозной DEMO smoke проверил сложную группу, корзину, один тестовый заказ, повтор подтверждения и устаревшую котировку: [отчёт](docs/verification/runtime-smoke-20261025.json).

Отдельный реальный [LLM harness-turn](docs/verification/llm-runtime-20261025.json) выполнил две относительные правки с сохранением состава группы через бесплатный NVIDIA backup после Gemma429.

Это не результат прогона всех [106 исследовательских сценариев](docs/research/agent-stress-analysis.md). Новые формулировки, качество многошагового NLU, полноценная смешанная корзина, сопоставимые реальные поставщики и интеграция frontend требуют отдельных проверок. SSE пока нет: доступны polling состояния run и JSON-журнал событий.

Для проверок без внешних API:

```bash
python -m pip install -c requirements.lock '.[dev]'
python -m pytest -q
```

Без `TEST_DATABASE_URL` PostgreSQL-интеграционные тесты явно пропускаются. Используйте отдельную тестовую БД. В настроенной среде владельца `py scripts/run_tests.py -q` жёстко использует `otravel_test`, а не рабочую `otravel`.

Сквозная локальная проверка: `python scripts/smoke_runtime.py --base-url http://localhost:8081`. Она оставляет синтетические сессии и один имитированный заказ; внешние API не вызывает.
