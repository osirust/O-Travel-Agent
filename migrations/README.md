# Схема PostgreSQL

Версия 1 определяется в `otravel/store.py` через SQLAlchemy MetaData. `Store.initialize()` идемпотентно создаёт отсутствующие таблицы и записывает версию 1 в `schema_versions`.

Это bootstrap, не механизм изменения существующих колонок. При следующем изменении схемы нужна явная новая миграция; `create_all` не обновляет уже существующие таблицы.

Состояние, ревизии и локальный результат операции фиксируются в коротких транзакциях. Внутри repository нет HTTP/LLM/tool вызовов. Pause/resume и создание demo-заказа увеличивают `state_version` для инвалидирования запоздавших результатов и прежних корзин. JSON `state.state_version` синхронизирован с колонкой версии.

`owner_token_hash` — внутреннее поле repository. HTTP-слой проверяет токен и исключает hash, поля lease и другие внутренние значения из публичных ответов.

Ограничения идемпотентности: `(session_id, client_message_id)` для входа, `(session_id, idempotency_key)` для подтверждения, отдельный UNIQUE `quote_id` для одного demo-заказа на корзину. Другой payload с прежним ключом отклоняется. Восстановление зависшего run помечает его interrupted и не повторяет бронирование.

`reserve_model_call` атомарно резервирует попытку через глобальную короткую advisory-транзакцию и событие `MODEL_CALL_STARTED`. Gemini и OpenRouter используют один общий live-счётчик за UTC-сутки; учитываются только события с `payload.provider` в `gemini`/`openrouter`, включая неудачные реальные попытки. Тестовые адаптеры (`injected_test_adapter`, `test_*`) используют отдельный общий счётчик, чтобы injected-тесты не расходовали live-бюджет приложения. Неизвестные имена отклоняются. Старые события сохраняются; изменение касается только фильтра счётчика, новая схема не требуется.

Бюджет переживает restart; ошибочные внешние попытки его не возвращают. Caller не дублирует `MODEL_CALL_STARTED` отдельно. Счётчик ограничивает только этот harness, а не весь аккаунт поставщика. Использование настоящего `LLMGateway` с фиктивным ключом всё равно считается live-попыткой: для изоляции тестов нужен injected adapter, а впоследствии отдельная тестовая БД.
