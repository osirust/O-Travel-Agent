## Принятые решения владельца

- **DEC-001 / редакция 2:** основная LLM через API. При её недоступности — явная ошибка, сохранённая поездка, формы и готовые демосценарии; полноценный свободный диалог без внешней LLM не требуется.
- **DEC-002 / редакция 2:** сразу несколько городов/отелей, несколько номеров, взрослые/дети и сложное распределение группы. География: Москва, Санкт-Петербург, Сочи, Казань, Стамбул, Анталья, Дубай. Опорный маршрут: Казань → Стамбул → Анталья → Казань. Не сокращать самостоятельно до одного города/номера.
- **DEC-003 / редакция 3:** гибрид с приоритетом live API/актуальных цен. Синтетический каталог нужен для тестов И продуктового demo fallback. При отказе источника разрешён смешанный план с маркировкой каждого компонента; его итог не выдаётся за полностью подтверждённую рыночную цену. Прежнее «синтетика только для фикстур» не действует.
- **DEC-004:** основной WOW-эффект — массовая пересборка затронутых компонентов со сравнением «Было → Стало», объяснением изменений и сохранением остальных пожеланий.
- **DEC-005:** сравнение реальных поставщиков обязательно; допустим один агрегатор с различимыми поставщиками. Два независимых API не обязательны. Цена и наличие повторно проверяются перед тестовым оформлением.
- **DEC-006:** после «подожди, я ещё дополню» дополнения сохраняются до явного «продолжай». Новая содержательная реплика и поздний ответ инструмента не возобновляют процесс автоматически. Обычный ответ на уточняющий вопрос отличается от такой явной паузы.
- На25 октября владелец подтвердил отсутствие и туристических API, и LLM API. Численные пределы городов/комнат/гостей, бюджет API и задержка не установлены. Смешивание источников разрешено; его технический контракт и возврат в live ещё требуют спецификации.
- Команда3: Глеб — fullstack с большим опытом frontend; роль и объём участия Жени ещё не согласованы. Владелец подтвердил, что другой участник делает полноценный frontend, не только макет; стек и API-контракт ещё не получены. Этот чат посвящён анализу harness/backend, параллельный интерфейс не создаётся.

## Открытые зависимости и findings

- **OTR-001 / OPEN_NO_MODEL_ACCESS:** на25 октября доступа к самой LLM нет; модель, квота и доступ жюри не выбраны. Управляемые ответы адаптера не подтверждают NLU на новых формулировках. Закрытие: подключённая модель и относящийся сквозной прогон.
- **OTR-002 / PRIMARY_SELECTED:** владелец выбрал официальный командный репозиторий. Личный backup для CV не настроен; правила будущего копирования и публикации не выводить из выбора основного repo.
- **OTR-003 / OPEN:** в официальном repo нет приложения/Docker/БД/интеграций. Корпус из106 случаев не закрывает этот разрыв. Закрытие: реализация после команды и новые относящиеся проверки.
- **OTR-004 / OPEN:** сохраняются вопросы редакции правил, прав и будущей публикации конкурсного решения. В текущем сеансе эти условия не переоценивались; лицензия не выбрана.
- **OTR-005 / OPEN:** владелец подтвердил отсутствие поисковых API-доступов при требовании live-цен. Действие: позже проверить доступ, режим, покрытие, разрешённое использование, стоимость и перепроверку тарифа. Закрытие: разрешённый доступ и относящийся live-прогон; sandbox или документация сами по себе не закрывают.
- **OTR-006 / OPEN_LIMITS_GEOGRAPHY_DEFINED:** география определена семью направлениями, но численные пределы сложной поездки и покрытие реального API не подтверждены. Действие: согласовать максимумы и проверить контракт источника. Закрытие: явный поддерживаемый периметр, совместимый с API.
- **OTR-007 / OPEN:** агрегатор и доступные сведения о разных реальных поставщиках не выбраны. DEC-005 разрешает один агрегатор, но не подтверждает наличие нужных данных. Закрытие: разрешённый источник, сопоставимые тарифы с различимыми поставщиками и относящийся прогон.
- **CORPUS-001…005 / OPEN_BEFORE_AUTOMATION:** фикстуры, часы, начальное состояние, операции сбоев и критерии проверки требуют спецификации. Факт, действие и условие закрытия записаны в основном обзоре и auditJSON.
- **CORPUS-006 / DOCUMENTED_NOT_SOURCE_DEFECT:** JSON изZIP имеет метаданные и массив `.tests`; исправлять исходник не нужно.
- **REVIEW-001…006 / OPEN:** конкретные неоднозначности STATE-08, DATE-08, MONEY-08, GROUP-02, ROUTE-05 и необходимость адаптировать SYSTEM-01 к согласованному резервному режиму. Уточнение DEC-001 не является выполненной фикстурой или PASS. Относящиеся действия и условия закрытия — в основном обзоре.
- **HARNESS-001…008 / OPEN:** режимы/DoD, канонический TripState/allocation, patch/undo/version, WAITING_USER, concurrency/recovery, frontend-формы, PG-журнал и проверяемость тестового плана. ## Что не выполнялось

Приложение/LLM/поисковые API/Docker и сценарии против приложения не запускались. Сервисы и WSL-дистрибутивы не запускались/не останавливали; выполнены только read-only inventory и pg_isready. Исходники сценариев не исправлялись. Не создавались аккаунты, ключи, брони или подписки. Runtime/harness не написан; текущие результаты — анализ, записи решений и наблюдения.

Ближайший шаг: ждать отдельной команды владельца. Перед ТЗ остаются модель/доступы/бюджет, численные пределы, каноническая схема/patch, frontend-контракт и среда. Формы/готовые сценарии при отказе LLM, один агрегатор, смешанный план и ожидание явного «продолжай» уже согласованы — повторно не спрашивать. До команды реализацию не начинать.
