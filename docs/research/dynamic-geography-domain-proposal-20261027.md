# Динамическая география: минимальный контракт

Предложение от 27.10.2026; реализация ещё не разрешена. Проверены текущие `domain.py`, `llm_contract.py`, `groq_prompt.py`, `groq_transport.py`, `store.py`. Предлагаемый контракт согласован с [проектом provider-слоя](dynamic-provider-geography-proposal-20261027.md). Код, БД, Native и API при подготовке не изменялись.

Сейчас ограничение находится в нескольких слоях: `canonical_city()` принимает встроенный справочник; schema для `set_origin`/`upsert_stay` перечисляет `known_cities()`; compact hints дополнительно проверяет фиксированный fingerprint этого перечисления. Поэтому глобальный поиск нельзя включить одной заменой словаря адаптера. LIVE8 остаётся отдельным проверенным ограниченным этапом.

## 1. Каноническое состояние

Добавить `TripState.location_refs`: словарь `place_id → CityRefSnapshot`, по умолчанию пустой и исключаемый из старой сериализации. Добавить nullable, также исключаемые при `None`, поля: `TripState.origin_place_id`, `Stay.place_id`, `Leg.origin_place_id/destination_place_id`, `RoutePolicy.end_place_id`. Строки `origin/city/destination/end_city` временно сохранить для совместимости frontend; при наличии ссылки они являются отображением подтверждённой записи.

```text
CityRefSnapshot = {place_id, ref_version, canonical_name, country_iso2,
  provider_bindings, timezone|null, identity_precision, source_fact_sha256}
```

`place_id` выдаёт сервер; это не придуманный ID поставщика. У LiteAPI binding может содержать только проверенные `country_code + provider_city_name`: внешний city ID и timezone не гарантированы. Duffel place ID/IATA/тип city-or-airport — отдельная привязка. Timezone хранится только с источником; timezone аэропорта не становится автоматически timezone города. Если название внутри страны неоднозначно, запись не считается уникальной физической географической идентичностью без дополнительного уточнения.

Физическую идентичность можно брать из [официального Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api): уникальный location ID, страна, административные уровни, координаты и timezone имеют отдельный географический источник. Связи с LiteAPI/Duffel проверяются независимо. Структура снимка допускает `geographic_source={provider,external_id}`; локальный `place_id` остаётся серверным. Нормализованный prefix-поиск API не исправляет произвольные опечатки: несколько кандидатов или предложенная замена требуют разрешения намерения.

Снимок включается в версию поездки. Обновление directory-cache не переписывает уже выбранные ссылки, имена или подтверждения. Изменение выбора/версии ссылки проходит обычную revision/CAS и отзывает устаревшие quotes/consent.

## 2. Валидация без глобального изменяемого справочника

Вложенные `Stay`/`Leg` не имеют доступа к родительскому `location_refs`: проверять там только ограниченную текстовую форму, не выполнять запросы и не читать глобальный cache. В `TripState` после построения проверить всю графовую связность: существование каждого `place_id`, совпадение ID/версии/страны/имени, точность отображаемых строк и принадлежность конечного города политике маршрута. Новое неизвестное имя без подходящей ссылки отклонять. Legacy-имена по-прежнему нормализовать существующим неизменяемым seed-справочником.

При синхронизации маршрута сравнивать идентичности ссылок, а не только одинаковые строки городов; производные legs получают те же refs. Это необходимо для одноимённых городов в разных странах. `route_policy.end_city` требует собственного `end_place_id`, а не отдельного обхода проверки.

Проверка структуры Pydantic не доказывает происхождение записи. API/Store перед сохранением обязаны сверить входные ref ID/версии и hash со строками durable catalog. Клиент и LLM не могут объявить свой snapshot проверенным. Для `initial_trip` с присланными refs нужна такая же проверка; неизвестные ссылки нового чистого стенда требуют разрешения через directory, а не доверия импортированному JSON. Pure domain получает только серверный verified bundle, копирует snapshot и применяет batch атомарно.

## 3. NLU → разрешение → выбор

Добавить одну операцию `resolve_place`: bounded `query`, `kind=country|city|airplace`, `role=origin|stay|route_end|guest_nationality`, optional country hint и стабильный target/creation alias. Это запрос разрешения, **не мутация TripState**. Harness отделяет его от domain-операций, сохраняет intake/run и вызывает provider resolver вне SQL-транзакции. Для отсутствующей страны, нескольких совпадений или отказа источника возвращается typed pending question; незатронутые однозначные факты сохраняются, настоящие противоречия продолжают блокировать batch.

Resolver возвращает `RESOLVED / AMBIGUOUS / NO_MATCH / UNAVAILABLE`, кандидатов с source facts и потраченный call budget. LLM-перевод/транслитерация — способ предложить поиск, не доказательство соответствия пользовательскому намерению. При выборе сервер составляет существующие `set_origin/upsert_stay/set_route_policy` с проверенными refs; для обычных дальнейших правок достаточно ссылки из текущего снимка. Отдельный public выбор использует resolution ID, candidate ID и expected state version. Никаких произвольных URL, model-forged snapshot или неявного ближайшего аэропорта.

«Аргентина» сначала становится CountryRef AR и вопросом о городе, а не отелем в придуманном городе. «Белгород» при выбранной Сербии допускает предложение подтверждённого кандидата Белград, с явным объяснением; подтверждённая привязка остаётся в этой поездке. «Стамбул в Сербии» сохраняется как противоречивый запрос: Стамбул/TR не переименовывается в Сербию и не заменяется произвольным похожим городом. Вопрос должен иметь одну цель подтверждения. Гражданство — отдельная role, не страна назначения.

## 4. Schema, wire и этап внедрения

Не перечислять мир в JSON Schema. Legacy city-enum сохранить, добавить только имена/refs уже разрешённых кандидатов конкретного запроса; всё новое свободное написание проходит `resolve_place`. Семь корневых полей ModelResult сохраняются. V2 wire по-прежнему использует конечный codebook типов и target IDs: добавляется зарегистрированный тип операции, а не глобальный список городов.

Нужна новая одобренная версия value-grammar fingerprints для location-ref полей и resolve-операции. Вместо отключения `_CITY_ENUM_SHA256` проверять точное соответствие динамического перечисления доверенному набору refs; записывать его hash вместе с canonical schema SHA. Старый v1-контракт и проверки остаются pinned. Decoder всё равно валидирует полный canonical schema; цена/наличие проверяются независимо через search/reprice.

Минимальная последовательность: durable directory records и snapshot DTO → parent/domain/API guards и миграция legacy seed → resolve/selection и pending-purpose lifecycle → schema/hints → адаптеры и фактический сквозной поиск. Проверки: два одноимённых города, RU/Latin опечатки, ложный ref/snapshot, чужой/устаревший resolution, restart и два worker, compound city+party+budget, undo/quote invalidity. DEMO остаётся семью синтетическими направлениями; отсутствие живого результата не создаёт синтетическую цену нового города. «Можно распознать город», «поставщик принимает запрос» и «тариф сейчас доступен» — три независимых результата.
