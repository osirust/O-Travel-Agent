ПРОДУКТ И ОГРАНИЧЕНИЯ
Команда 3 человека. Мы создаём собственный управляемый harness вокруг LLM, не переезжаем сейчас на LangGraph/Redis/Kafka/рой агентов. BackendFastAPI+PostgreSQL+DockerCompose. Главное: составные изменения поездки, группы/дети/несколько номеров/городов, сохранение остальных требований, проверка совместимости и бюджета, «Было→Стало», явная пауза до «продолжай», восстановление после ошибок.
Начальный каталог: Москва, СПб, Сочи, Казань, Стамбул, Анталья, Дубай. Приоритет внешнего поиска, синтетический резерв обязателен. Смешанные планы разрешены с маркировкой каждого компонента. Готовность реального бронирования не утверждаем: все покупки имитируются, настоящие supplier orders и платежи не создаются. Одного агрегатора с различимыми поставщиками достаточно, но сравнимость тарифов нужно доказать.

ЧТО НАДЁЖНО ПРОВЕРЕНО В ОСНОВАНИИ
1. Docker app+PG стартовали на новом пустом volume; схема создаётся автоматически. Данные сохраняются после restart.
2. PostgreSQL хранит sessions/messages/agent_runs/agent_events/state_revisions/quotes/demo_orders. Отдельные DBotravel(рабочая),otravel_test(накопленные тесты),otravel_local_eval(локальные реальные LLM-прогоны). Веса модели и API-ключи в SQL не грузятся. Ключи в ignored native.env0600; API session tokens в БД только как hash. Глобальный каталог отелей не импортирован.
3. CanonicalTripState со стабильными ID людей/групп/остановок/комнат/плеч; constraints hard/soft; изменения через whitelist операций. Search policy тоже версионна. Предварительные ресурсные guards10 людей/4 остановки/5 комнат — не утверждённые владельцем продуктовые пределы.
4. Sequence/idempotency_key/payloadfingerprint/CAS/один active изменяющий run/session. Повтор сообщения/подтверждения не создаёт второе действие. Другой payload с тем же ключом отклоняется.
5. OwnerBearer авторизация сессий и runs; чужой токен не даёт читать поездку. Перед каждым model/tool dispatch проверяются lease/version/pause. Поздний ответ не должен перезаписать более новую поездку. Транзакции короткие, HTTP вне SQL транзакций.
6. DEMO полный путь: Казань→Стамбул→Анталья→Казань,9 путешественников/2 семьи/3 номеранаостановку, поиск/проверка/котировка/один BOOKED_DEMO/idempotency/stalequote.
7. Undo создаёт новую revision, не оживляет старую цену/согласие, не отменяет существующие заказы. Cancel отдельно останавливает обработку; это не undo и не pause. История первого предложения доступна как historical-only. Частичный возврат отеля с сохранением актуального транспорта проверен typed-fixture; смена транспорта в его setup была через Store, publiclegmode setter ещё нет.
8. Настоящий SIGKILL своей временной PG→503JSON при DBdown→WALrecovery: trip/version/pause/token/order сохранились, повтор confirm тотже order, partialintake0. Ранее был 500 из-за socket.gaierror; исправление проверено новым crash-прогоном. Старые FAIL сохранены. Это не доказательство всех распределённых/дисковых отказов.
