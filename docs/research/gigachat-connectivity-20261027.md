# Проверка доступа к GigaChat

27 октября проверены официальный OAuth и адрес `https://api.giga.chat/v1`. Использован ранее проверенный публичный CA; проверка цепочки и имени сервера включена. VPN, системные маршруты и доверенные сертификаты ОС не менялись.

OAuth вернул **HTTP200** при локальном разрешении официального имени на совпавший адрес из системного DNS и Cloudflare DoH. Ключ принят, токен находился только в памяти и был очищен при закрытии клиента. Список моделей получить не удалось: TCP к API устанавливается, TLS завершается timeout. То же наблюдается в Windows/WSL, с TLS1.2 и HTTP1.1; это не доказанная ошибка ключа и не доказанная исчерпанная квота. Генераций GigaChat — **0**.

Доказательства: [проверка авторизации с исходным SNI](../verification/gigachat-verified-dns-readiness-20261027.json), [первый поздний запрос](../verification/gigachat-late-readiness-20261027.json). Новым аккаунтам нужен [текущий официальный API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api); старый URL не подставляется вместо него.

## Предложение для отдельной проверки сети

Если владелец разрешит, проверить в Happ исключение **только для полного имени `api.giga.chat`**: Direct вместо VPN. Остальные домены, подписка, выбранный сервер и правила остаются прежними. Перед изменением сохранить настройки приватно; после — проверить API и работу Codex. При отсутствии эффекта восстановить правило. Это предложение, оно **не применено**: ранее владелец просил настройки VPN не трогать.

До подтверждённого доступа к списку моделей и бесплатному остатку GigaChat не становится основной LLM. Прогоны продолжаются через разрешённые Groq/Z.ai; при отказе модели сохраняются поездка и доступ к типизированным формам/явному DEMO.
