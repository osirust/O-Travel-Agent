# R18: туристический сценарий без LLM

На точном Git-коммите `4645c24` / package `4e383ff6` проверены публичные API приложения через ASGI и новый изолированный PostgreSQL. Входные данные переданы типизированно. Это **проверка форм и команд, не понимания свободного текста**. LLM-ключей и model HTTP нет; вызов NoModel запрещён, в ledger ноль MODEL_CALL_STARTED.

Маршрут: Казань → Стамбул 10–13 ноября → Анталья 13–19 ноября 2026 → Казань 19 ноября. Двое взрослых с неизвестным возрастом и дети 7/4 лет. В каждом городе два номера: первый взрослый с обоими детьми, второй взрослый отдельно. Бюджет 1 180 000 RUB, гражданство RU.

- 22 реальных туристических HTTP: 19 ответов 200 и 3 ответа 201, при лимите 40. Это 2 hotel lookup, 2 rates, 3 Duffel search, 2 hotel details, 4 sandbox prebook, 6 flight refresh и 3 CBR. Автоматических повторов запроса нет.
- Два отеля, четыре номера и три перелёта — SANDBOX; два трансфера — явно DEMO. Покрытие полное. После prebook адаптер подтвердил распределение гостей и включение сборов. Для рейсов проверены те же четыре пассажира, пары KZN → IST → AYT → KZN, даты и хронология UTC.
- Фото двух отелей связаны с точными выбранными source hotel ID. Изображения отдельно не скачивались. Media не подтверждает реальное наличие.
- После поиска и повторного preview итог составляет `37616580` minor RUB, то есть **376 165,80 RUB**, при бюджете 1 180 000 RUB. Пересчёт EUR справочный, по CBR от 28.10; банковские комиссии неизвестны.
- Второй явный preview отозвал первый quote. Старый confirm получил 409, новый — 200, повтор того же согласия — 200 и тот же **один BOOKED_DEMO**. На confirm туристических HTTP нет; брони и оплаты у поставщика нет.

Мой финальный oracle ошибочно ожидал неизменную revision после создания заказа. `Store.confirm_quote` намеренно делает `state_version + 1`; все остальные факты поездки совпадают. Поэтому исходный actor сохранён как 13 PASS / 1 FAIL. В первом read-only диагнозе также ошибочно ожидалось название статуса `revoked`, тогда как код использует `stale`; результат 10/1 сохранён. Исправленный **только read-only** addendum дал 11/11, без повторных API, заказов, записей в БД или изменения core.

Итог БД: один BOOKED_DEMO и одно событие создания заказа, два quote со статусами stale/ordered, ноль pending/active/model starts. Старые два setup refusal и исходный final FAIL не перезаписаны. Native8084/8091, их профили и данные не использованы.
