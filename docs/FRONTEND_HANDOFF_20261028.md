## Точки подключения

Полный [контракт API](FRONTEND_CONTRACT.md), [DTO фотографий](HOTEL_MEDIA.md) и OpenAPI `/docs`. Здесь `S=/api/v1/sessions/{session_id}`:

| Действие | Использовать |
| --- | --- |
| Начать поездку | `POST /api/v1/sessions`; сохранить одноразовый `session_token` локально и передавать Bearer. |
| Восстановить страницу | `GET S`; состояние, версия и pending приходят с backend. |
| Написать/показать прогресс | `POST S/messages`, затем run/SSE по контракту. UUID сообщения и expected_version сохранять для повторов. |
| Отобразить ответ | У целого GET run — `run.result.reply`; `assistant_message` является объектом с `.text`. Не парсить текст в данные поездки. |
| Карточки и фотографии | Сохранённые plans/offers; `GET S/media?plan_id=...&state_version=...`. Связь по offer/component/hotel ID, а не по порядку случайных картинок. |
| Суммы | `total_minor`/`amount_minor` и currency. Для RUB/USD/EUR делить на100; не делать повторный FX-пересчёт уже приведённого итога. Суммы поставщиков и справочный пересчёт различать. |
| Вопрос агенту | Показывать `pending_question.text`; поле/target нужны форме. Бюджет и другие уже сохранённые факты не очищать из-за нового вопроса. |
| Тестовое оформление | Preview → показать актуальные сумму/источники → явный confirm. После заказа перечитать `GET S`: версия увеличивается. Один и тот же consent повторять только с тем же UUID/параметрами. |

Не превращать `DEMO`, `SANDBOX`, `LIVE_INDICATIVE` в подтверждённое наличие. Фото не подтверждает тариф. При пустой галерее нужна заглушка. При409 перечитать snapshot и получить новое согласие; при429/сбое сохранить диалог и дать доступ к формам. При паузе ждать явного продолжения.
