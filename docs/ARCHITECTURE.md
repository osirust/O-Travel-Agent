# Архитектурный набросок

Цель фундамента — сделать один небольшой сценарий обработки запроса о путешествии воспроизводимым и понятным для четырёх участников. Полные условия трека пока не подтверждены; архитектура не фиксирует будущий продукт.

## Границы

```text
Пользовательский ввод
        |
Проверка и нормализация запроса
        |
Прикладной сценарий
        |-----------------------|
Порт каталога              Порт модели
        |                       |
Демонстрационные данные    Детерминированный mock
        |-----------------------|
Проверяемый JSON-ответ с ограничениями
```

Прикладной сценарий зависит от небольших контрактов, а конкретные источники данных и провайдеры подключаются через адаптеры. Это позволяет менять способ запуска модели, сохраняя общую обработку запроса.

| Часть | Ответственность | Ограничение фундамента |
| --- | --- | --- |
| Вход и выход | Проверить обязательные поля, вернуть понятные ошибки и структурированный результат | Это демонстрационный контракт, который уточняется после публикации задания |
| Прикладной сценарий | Связать проверку запроса, данные и ответ | Обрабатывает только явно поддерживаемый сценарий |
| Порт каталога | Получить варианты из источника данных | Примеры синтетические; актуальность, цены и доступность не подтверждаются |
| Порт модели | Изолировать вызов будущего LLM-провайдера | Рабочая реализация на этапе фундамента — mock |
| Адаптеры | Преобразовать внешний формат в согласованный внутренний | Local/API остаются вариантами будущей интеграции |
| Проверки | Подтвердить контракты, ошибки входа и воспроизводимость | Не подтверждают качество настоящей модели или внешних сервисов |

## Что должно работать сначала

Локальный запуск на Python со стандартной библиотекой читает демонстрационный запрос и выдаёт детерминированный JSON. Для этого не нужны ключи API, сеть, GPU или скачивание весов. Примеры намеренно небольшие: их можно прочитать и проверить вручную.

Точка входа каркаса:

```powershell
py -m aegml --request examples/request.json
```

Ввод пока структурированный; разбор свободного текста не реализован. Неполный запрос приводит к явным уточняющим вопросам или ошибкам в зависимости от отсутствующих либо некорректных полей.

Каркас не содержит настоящую LLM, подключение к бронированию или готовый веб-интерфейс. В структурированном сценарии метод модели не вызывается: `llm.called=false`. Показ mock-сценария подтверждает только внутреннюю связность каркаса.

## Решение по LLM — после уточнения условий

Варианты локальной модели и API обсуждаются на уровне одного интерфейса. Выбор модели, доступных мощностей, квот и требований к размещению пока открыт. Упоминание конкретной модели в обсуждении команды не подтверждает её доступность или требование использовать её на хакатоне.

Настройка `AEGML_LLM_MODE` предусматривает значения `mock`, `local` и `api`. Рабочий режим фундамента — `mock`; выбор `local` или `api` сам по себе не подключает настоящую модель.

Перед подключением провайдера нужно отдельно проверить доступ, формат вызовов, лимиты, задержку, обработку ошибок и стоимость либо ресурсные ограничения. Для продолжения работы без провайдера нужно явно выбрать `mock`; автоматического fallback нет. Демонстрационный режим явно отмечается в ответе.

## Последовательность расширения

Сначала согласуем задание и минимальный сценарий, затем подключаем один разрешённый источник данных и один провайдер. После этого проверяем полный путь запроса и выбираем подходящий интерфейс. Реальные действия с бронированием рассматриваем только при наличии разрешённого API, понятных правил и отдельного подтверждения пользователя.
