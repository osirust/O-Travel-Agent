# Запуск для записи демонстрации

Нужен работающий Docker с Compose. Получить проект можно архивом с GitHub или через Git. PostgreSQL, backend и готовый интерфейс поднимаются в контейнерах; отдельно Python, Node и WSL устанавливать не требуется.

Три туристических ключа — LiteAPI sandbox, Duffel test и SerpApi — уже заполнены в отдельно передаваемом приватном `.env`. Получать их заново не требуется. Свой доступ к LLM указывает записывающий. В GitHub ключи переданы организаторам в зашифрованном `secrets.env.age`; для записи нужен отдельный приватный `.env`, а не ключ расшифрования организаторов.

1. Открыть [репозиторий на ветке main](https://github.com/ostrovok-hackathon-2026/aegml/tree/main) под GitHub-аккаунтом с доступом. Нажать **Code → Download ZIP** и распаковать архив. Вместо этого можно получить готовый архив от команды: код тот же. Локальные ссылки вида `E:/...` и `C:/...` работают только на компьютере отправителя — передавать нужно сами файлы.
2. Положить полученный приватно конфиг рядом с `docker-compose.yml` под именем `.env` (не `.env.txt`). Конфиг передаётся записывающему отдельно в личном канале; не помещать его в Git и не показывать ключи в видео.
3. В этом же файле указать формат, адрес, модель и ключ своего LLM API:

```dotenv
LLM_PROVIDER=external
LLM_API_FORMAT=openai
LLM_BASE_URL=https://your-llm-server.example/v1
LLM_MODEL=your-model-id
LLM_API_KEY=YOUR_API_KEY
LLM_EXTERNAL_API_CONFIRMED=true
```

Для родного Gemini используйте `LLM_API_FORMAT=gemini`, для Anthropic — `anthropic`, с соответствующим адресом API. Все три примера и необязательные настройки есть в [README](../README.md#как-подключить-llm-жюри). OpenAI-совместимый формат подходит и для других производителей моделей. Ключи разных поставщиков не взаимозаменяемы; конкретная модель должна соблюдать JSON-контракт операций.

Проверенный отдельный вариант: `LLM_PROVIDER=zai`, `ZAI_MODEL=glm-4.5-flash`, `ZAI_API_KEY` и `ZAI_FREE_TIER_CONFIRMED=true`. Последнее подтверждает бесплатный Standard API вашего аккаунта; Coding Plan использует другой режим доступа.

4. В терминале из папки проекта выполнить:

```sh
docker compose up --build
```

5. Дождаться готовности `app` и `web`; открыть http://localhost:8080. Если этот порт занят, изменить `APP_PORT` в `.env`, например на `8082`, и открыть соответствующий адрес. Если Docker отдельно сообщает о занятом порте backend `8081`, задать свободный `BACKEND_PORT`, например `8086`; внутренние адреса сервисов менять не требуется.

В конфиге туристического стенда должны быть `DEFAULT_SEARCH_MODE=HYBRID`, `DEFAULT_HOTEL_PROVIDER=liteapi`, `DEFAULT_FLIGHT_PROVIDER=duffel`, `LITEAPI_MODE=sandbox`, ключи LiteAPI/Duffel/SerpApi, подтверждение Free SerpApi и `REFERENCE_FX_ENABLED=true`. Ключи остаются на backend. API-поставщики требуют интернет, а PostgreSQL хранится в отдельном Docker volume.

## Запись экрана с микрофоном в Windows 11

1. Открыть приложение **«Ножницы»** через меню «Пуск» и выбрать режим **«Запись»** со значком видеокамеры.
2. Нажать **«Создать»**, выделить область с браузером и включить значок **микрофона** на панели записи. При запросе Windows разрешить доступ к микрофону. Если звуки компьютера для демонстрации не нужны, выключить их отдельно.
3. Записать десять секунд с голосом, остановить и прослушать результат. После проверки начать основной ролик.
4. Нажать **«Начать»**, показать приложение и объяснить действия голосом. После завершения нажать **«Стоп»** и сохранить видео в MP4 через кнопку сохранения или `Ctrl+S`.

Вариант для записи окна браузера через Xbox Game Bar: `Win+G` → панель «Записать» → включить микрофон. `Win+Alt+R` начинает и останавливает запись; `Win+Alt+M` переключает микрофон. MP4 сохраняется в папку **«Видео → Клипы»** (`Videos/Captures`).

Инструкции Microsoft: [«Ножницы» и микрофон](https://www.microsoft.com/en-us/windows/learning-center/how-to-use-snipping-tool-on-windows-screenshots-shortcuts-and-screen-recordings), [запись через Xbox Game Bar](https://support.microsoft.com/en-us/accessibility/windows/use-a-screen-reader-to-record-your-screen-with-xbox-game-bar).

Перед записью закрыть вкладки с ключами и конфигурацией, отключить уведомления и оставить открытым только приложение. На рабочем стенде команды используется http://localhost:18082/#studio; после самостоятельного запуска через Compose — http://localhost:8080.

Успешный статус обработки сообщения подтверждает завершение запуска. Для показа фотографий дополнительно открыть вкладку **«Отели»** и дождаться карточек с фото конкретного отеля. DEMO-компонент целого плана может не иметь фотографии; это не подтверждение неисправности LLM и не повод подменять изображение. Доступность внешних источников и квоты могут отличаться от последней проверки команды.

После записи загрузить видео по ссылке, доступной без авторизации, и передать её команде. Ссылка добавляется в начало README; финальный тег `submission` ставится на последнем коммите `main` после этого дополнения.

## Что показать в видео

- Новый диалог с конкретными датами, составом, количеством номеров и бюджетом. Отсутствующие данные агент уточняет; гражданство указывается явно. Для первой проверки можно использовать запрос ниже — этот сценарий проходил через видимый интерфейс с реальной LLM и туристическими API:

  > Хочу поездку из Москвы в Стамбул и обратно. Заезд 10.11.2026, выезд 13.11.2026. Еду один взрослый, детей нет. Нужен один гостиничный номер только для меня. Гражданство Россия. Общий бюджет 100000 рублей на всю поездку. Подбери отель и перелёты.

- Затем сложную поездку: Казань → Стамбул 10–13 ноября 2026 → Анталья 13–17 ноября → Казань; двое взрослых, дети 7 и 4 лет, два номера, по одному взрослому и ребёнку в каждом; гражданство Россия, общий бюджет 500000 рублей. Перед записью отдельно проверить этот разговор на подключённой модели: успешная проверка простого маршрута не подтверждает все сложные варианты.
- Вкладка «Отели»: карточки, фотографии конкретного отеля, цены за проживание и маркировка ориентировочных данных. Если фото не пришло, городская иллюстрация не выдаётся за фото отеля.
- Изменение даты, состава или бюджета; сравнение сохранённых условий и актуальных вариантов. Устаревшее предложение не используется для подтверждения.
- Одно уточнение или противоречие: опечатка в городе, несовпадение страны и города либо выезд раньше заезда. Показать необходимый вопрос, а затем ответить на него.
- Паузу «Подожди, я ещё дополню», дополнение к запросу и явное «Продолжай». Во время паузы агент не должен самостоятельно возобновлять поиск.
- Во вкладке «Перелёты» переключить «Класс перелёта»: эконом / бизнес. Это меняет отдельный поиск перелётов, а не класс или итог котировки целого плана. Если Google Flights не вернул предложений, показать объяснение; это не доказывает отсутствие рейсов.
- Вкладка «Предложение от агента»: выбрать **целый план**. Для него в правой панели есть «Посмотреть условия примера» → повторная проверка → явное подтверждение → «Сохранить пример».

Отдельная «Корзина» карточек отелей/перелётов — предварительный выбор в браузере. Она не является серверной котировкой; кнопка оплаты в ней отключена. Для тестового заказа использовать целый план и путь выше. Реальные брони, оплата и банковская карта не используются.

## Точный путь к тестовому оформлению

1. На главной нажать «Спланировать поездку». В рабочем окне открыть параметры через город в верхней панели или карандаш рядом с «Моя поездка».
2. В «Маршрут» заполнить отправление, остановки, заезд/выезд и завершение маршрута. В «Гости и номера» добавить участников, возраст детей, гражданство и распределить каждого по номеру. В «Бюджет и условия» указать общий бюджет. Нажать «Сохранить».
3. Открыть «Предложение от агента» и дождаться целого плана. «Посмотреть состав» выбирает этот план и открывает его детали. Закрыть детали.
4. В панели «Моя поездка» нажать «Посмотреть условия примера». Если ранее выбраны отдельные карточки в браузерную корзину, ссылка называется «Проверить целый план агента»: она проверяет отдельный план агента, а не эти карточки. На телефоне панель открывается нижней вкладкой «Поездка».
5. Дождаться окна «Проверим детали поездки» с новой ценой и сроком действия. Поставить галочку «Подтверждаю состав и сумму примера поездки» и нажать «Сохранить пример». Должно появиться сообщение, что пример сохранён и бронирование не создано.

Если целый план отсутствует, содержит незакрытые ограничения или поездка ждёт уточнения/стоит на паузе, тестовое оформление недоступно. Сначала ответить на вопрос или скорректировать условия; предварительная корзина из отдельных карточек не заменяет полный план. После изменения поездки нужна новая проверка и новое согласие. Если срок проверки истёк, закрыть окно и проверить план заново.

Если поставщик не подтвердил тариф или наличие, показать отказ и следующий шаг; не выдавать неподтверждённую корзину за оформленную. Для воспроизводимого локального заказа можно отдельно использовать явно обозначенный DEMO-пример. Такой результат не является реальной бронью.

## Если LLM недоступна

429, тайм-аут или ошибка модели сохраняют поездку. Доступны формы и явный пример; не выдавать их за успешный свободный диалог. Не перезапускать запрос бесконечно и не менять UUID уже принятого сообщения. После изменения `.env` пересоздать только приложение: `docker compose up -d app web`.

Другие реализованные адаптеры: OpenRouter (`OPENROUTER_API_KEY`, `OPENROUTER_MODEL` с суффиксом `:free`), Groq (`GROQ_API_KEY`, `GROQ_MODEL`, `GROQ_FREE_TIER_CONFIRMED=true`), Cloudflare (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_MODEL`, `CLOUDFLARE_FREE_TIER_CONFIRMED=true`), Gemini и GigaChat. Выбирать адаптер через `LLM_PROVIDER`. GigaChat в среде владельца пока не прошёл TLS-соединение с inference API, поэтому для записи не рекомендован как единственный вариант.

Для сдачи секреты передаются по [официальной инструкции](SUBMISSION.md) в бинарном `secrets.env.age`. Приватный `.env` записывающего и зашифрованный комплект проверяющих — разные артефакты. Туристические ключи проекта уже подготовлены; **свой LLM-доступ добавляет принимающая сторона**. Без него доступны формы и DEMO, а свободный диалог сообщает о недоступной модели.
