# Travel Studio: React + JavaScript

Реализация согласованных экранов 1 и 2 находится в `frontend/`. Основа backend — ветка `backend/harness-foundation`, commit `9ddfcda`; frontend не заменяет harness и PostgreSQL.

## Запуск всего приложения

```sh
docker compose up --build -d
```

- Интерфейс и API через proxy: http://localhost:8080.
- Swagger: http://localhost:8080/docs.
- Прямой backend для разработки: http://localhost:8081.
- PostgreSQL работает внутри Docker; наружу порт БД не опубликован.

`APP_PORT` меняет порт интерфейса, `BACKEND_PORT` — прямого backend. Имеющиеся volumes при обычном перезапуске сохраняются.

## Разработка

Node.js 24, React, JavaScript, Vite. TypeScript не используется.

```sh
cd frontend
npm ci
npm run dev
```

Vite открывается на http://localhost:5173. `/api`, `/health` и документация проксируются к `http://127.0.0.1:8081`. Другой адрес задаётся через `BACKEND_URL` в `frontend/.env.local`; пример находится рядом. Ключи провайдеров в этот файл не помещаются.

```sh
npm test
npm run build
```

## API отелей и перелётов

Внешние вызовы выполняют уже существующие серверные адаптеры. Frontend сохраняет `trip.search_policy` через `/commands`, запускает `/search` и получает целые планы через polling run. Отдельный `/live/search` не подменяет проверенную корзину.

| Сервис | Назначение | Доступ и границы |
|---|---|---|
| [LiteAPI](https://docs.liteapi.travel/reference/post_hotels-rates) | Отели, тарифы, размещение; фотографии через отдельный media endpoint backend | [Бесплатный sandbox-ключ собственного аккаунта](https://docs.liteapi.travel/docs/booking-a-room), `LITEAPI_API_KEY`, `LITEAPI_MODE=sandbox`. Тестовые предложения, не реальные брони |
| [Duffel](https://duffel.com/docs/guides/getting-started-with-flights) | Перелёты, пассажиры, маршруты, обновление предложения | [Тестовый токен из кабинета](https://duffel.com/docs/api/overview/test-mode), `DUFFEL_ACCESS_TOKEN`. Sandbox-цены и расписания не следует выдавать за реальные |
| [SerpApi Google Flights](https://serpapi.com/google-flights-api), [Google Hotels](https://serpapi.com/google-hotels-api) | Поисковые цены | `SERPAPI_API_KEY`; [Free: 250 запросов в месяц](https://serpapi.com/pricing), проверено по странице 26.10.2026. Это ориентировочные данные без гарантии наличия |
| [Travelpayouts / Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163) | Архивные цены на первое плечо | `TRAVELPAYOUTS_API_TOKEN`; цена не подтверждает наличие и не является ценой группы. Доступ требует своего аккаунта |

Все три сервиса требуют ключ/токен собственного аккаунта. Публичный URL документации не даёт анонимный доступ к поиску. Доступность аккаунта и конкретной квоты не подтверждается одной настройкой.

Для поиска через API скопируйте корневой `.env.example` в `.env`, заполните серверные ключи и выберите:

```dotenv
DEFAULT_SEARCH_MODE=HYBRID
DEFAULT_HOTEL_PROVIDER=liteapi
DEFAULT_FLIGHT_PROVIDER=duffel
LITEAPI_MODE=sandbox
```

`SERPAPI_FREE_TIER_CONFIRMED=true` задаётся только после подтверждения подходящего бесплатного аккаунта. Внешние источники можно выбрать в «Параметры → Источники». Гражданство заполняется явно; оно не определяется по языку. Появление ключей не меняет сохранённую политику существующей поездки.

По умолчанию переносимый запуск остаётся в DEMO. Для свободного диалога нужен отдельно настроенный LLM-провайдер; без него доступны формы, управление и явно загружаемый демонстрационный маршрут. Платные fallback, реальные бронирования и списания не добавлены.

## Поведение интерфейса

- Hero содержит одну кнопку «Спланировать поездку»; поля ввода и ссылки на DEMO на нём нет. Переход открывает рабочую область, но не отправляет запрос.
- Сессия и token сохраняются в браузере. Токен используется только в Bearer-заголовке своего backend.
- До POST сохраняются UUID, payload и версия. Неопределённая доставка повторяется с прежними параметрами по действию пользователя.
- Терминальные run восстанавливаются из истории; старые планы другой версии или поездки не становятся текущими.
- На паузе сообщения принимаются, но не считаются уже применёнными; продолжение требует явного действия.
- Фото запрашиваются через `GET S/media` отдельно. Проверяются session/version/plan/offer, старый запрос отменяется. Сбой картинки не блокирует выбор.
- Локальные изображения направлений созданы встроенным imagegen и подписаны как иллюстрации, а не фото конкретного отеля. Промпты сохранены в `frontend/public/images/SOURCES.json`.
- Checkout получает новый quote и отдельное согласие. Повтор confirm сохраняет исходные quote, версии и idempotency key. Заказ всегда тестовый.
- На телефоне используются вкладки «Агент», «Варианты», «Поездка».
- В центральной области вкладки «Отели» и «Перелёты» запрашивают отдельные компоненты через `/live/search`, не добавляя их в корзину. Для первого города доступны SerpApi (один номер) и LiteAPI sandbox (несколько номеров и явно указанное гражданство). Для перелётов доступны SerpApi, Duffel test и Travelpayouts; последний показывает только первое плечо и требует отдельный токен. Доступ к каждому источнику зависит от настроенного ключа и его условий.
- В выдаче SerpApi отображаются рейтинг, количество отзывов и до пяти фотографий, привязанных к записи конкретного отеля. Если фото недоступно, показывается подписанная иллюстрация города. На странице отображаются только безопасные адреса Google CDN; фото загружаются без передачи адреса страницы в Referer.
- Отзывы загружаются только по кнопке «Читать отзывы» через авторизованный `GET /api/v1/sessions/{id}/hotel-reviews?offer_id=...`. Сервер берёт идентификатор отеля из результата текущей сессии и версии, показывает до 10 отзывов и их исходный источник. Отдельный запрос может использовать квоту SerpApi; язык текста зависит от ответа источника.

## Границы проверки

Проверены сборка, тесты состояния/денег/идемпотентности, сохранение неполной поездки с группами и номерами через локальный backend и сквозной DEMO-путь. В локальной конфигурации SerpApi вернул отели с фотографиями и рейтингами, а отзывы выбранного отеля загрузились; проверены отказ для чужой сессии и неизвестного отеля. Это не подтверждение наличия, итоговых сборов или бронирования. 27.10.2026 запрос каталога LiteAPI в текущей конфигурации вернул HTTP 401. Токен Duffel, считанный со снимка, также ранее получил HTTP 401; правильность распознавания токенов не подтверждена. Ключ Travelpayouts не настроен. Свободный NLU в текущем локальном запуске не подключён.
