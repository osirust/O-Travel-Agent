## Смысл реплики: PROPOSE, ASK и CHANGE

У turn должен быть явный ожидаемый речевой акт и целевой slot:

- **PROPOSE**: «а может Стамбул?», «предложи пересадку, если дешевле», сравнение альтернатив. Можно показать кандидата/компромисс; это само по себе не разрешение заменить страну, origin или обязательное условие.
- **ASK**: вопрос о факте, вопрос пользователя, нехватка данных или несовместимые условия. Ответ/уточнение сохраняет прежнее состояние, кроме отдельно названных однозначных фактов.
- **CHANGE**: явная правка выбранного slot с достаточным контекстом и полномочиями. Достаточность подтверждения задаётся policy до прогона; модельный `PROPOSE_CHANGE` сам не авторизует запись.

«Хочу в Стамбул» может быть новым запросом назначения, а в другом контексте — обсуждением альтернативы. Единственность распознанного города не доказывает разрешение изменить уже выбранную страну. Для «Сербия → Стамбул?» сначала сохраняется Сербия и объясняется, что Стамбул находится в Турции, с уточнением замены страны. Город назначения не становится городом отправления.

Короткое «1» относится к **актуальному** вопросу. Если «я взрослый» уже сохранило одного взрослого и новый вопрос — о детях, «1» может означать одного ребёнка; adult-count остаётся один. Нельзя ни дублировать взрослого, ни применять старое значение к новому slot. Для предложения пересадки разрешённое сравнение не означает снятие hard `nonstop`; для двух тарифов нельзя объединять завтрак/отмену из разных rate IDs.

У CONFLICT-09 исходный human-oracle смешивает изменение бюджета и уменьшение фактической цены. Уменьшить **параметр бюджета** на 30 000, сохранив компоненты и их стоимость, возможно; результат может стать over-budget. Нельзя обещать, что сама цена снизилась. До binding нужно принять эту семантику либо явно описать, что пользователь просит скидку. Исходный текст сохраняется, спорное ожидание не превращается в автоматический evaluator.

**Неизвестное гражданство не означает ни безвизовый, ни визовый режим.** `citizenship=null` оставляет eligibility неизвестным. В CONFLICT-05 исходник это прямо требует; дефект не приписывается самому приложенному audit. Для утверждения нужны гражданство/документы, назначение и транзит, даты и актуальный источник; отсутствие поля нельзя превратить в `visa_free=true` или `false`.

## Формат oracle_bindings и результат исполнения

Новый [пакет oracle_bindings](../../fixtures/evaluation/oracle_bindings/README.md) хранит 106 **неисполненных** bindings с исходными/новыми record SHA, revision, полными репликами и отдельным обязательным `original_behavior` check. У cases с пустыми flags тоже есть непустой обязательный check: нельзя получить PASS через `all([])`.

`oracle_flags_proposed` — source annotations. Адаптер связывает флаг с конкретным surface, expression, исходным baseline, clock, fixtures/fault и evaluator revision. Пока любой обязательный check `UNBOUND`, case `BLOCKED` для полной приёмки. `UNKNOWN` evaluator, неисполненная setup-action или неподдержанный assertion также не дают PASS. Предложенные schema/data files не реализуют runner.

Bindings и результаты разделены. В binding запрещено писать PASS. Отдельный execution report обязан хранить case/turn/check IDs, binding revision/SHA, реально исполненный слой, ожидание/наблюдение, модель/попытки, state revisions, messages/events, source/quote/order IDs и список skipped/unbound checks. Никаких токенов сессии, ключей, DSN или сырых provider credentials.

Признаки готовности конкретного binding: полный initial state или явно fresh session; speech-act/slot policy; checkpoint clocks/TZ; deterministic source snapshots и ID aliases; seed/параметры модели либо явная неподдержка seed; для fault — точная точка и расписание отказа; разрешённые side effects и состояние после каждого turn. Принятые допущения фиксируются **до** model run, а не после неудачного ответа.

## Как читать итог

Показывать отдельно: actual local NLU, actual remote NLU, typed/domain, PG/API, provider contract, UI и faults. Для actual106 denominator — 106 исходных case IDs; дополнительно turns/checks с `FAIL/BLOCKED/UNSUPPORTED/NOT_RUN`, попытки и задержки. Общий зелёный pytest или любое число helper tests не меняет этот denominator и не закрывает исходный корпус. Передача тестировщику — после согласованной серии, с первыми FAIL, последними retests и открытыми ограничениями.
