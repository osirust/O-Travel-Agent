# DEMO-трансфер для выбранных мировых направлений

Это узкое дополнение существующего разрешённого смешанного режима, а не реальный поставщик трансферов. Гостиницы и перелёты мирового маршрута по-прежнему должны приходить от внешних источников с их собственными проверками. Их DEMO-подстановка не включается.

Условия: `HYBRID`, `search_policy.demo_fallback=true`, у остановки есть точный серверный `CityRefSnapshot`, даты, состав группы; все остальные требуемые компоненты уже покрыты и не имеют блокирующих ошибок. Если остался только трансфер, конечный генератор может добавить по одному явно синтетическому предложению на такую остановку. При `demo_fallback=false`, отсутствующей ссылке, неподтверждённых отеле/перелёте или обязательных сборах план остаётся неполным. Режим DEMO для мировой географии не расширяется.

Предложение называется **«Демонстрационный трансфер; стоимость и наличие вымышлены. Трансфер поставщика не бронируется.»** Его `provider=demo_place_transfer`, `source_type=DEMO`, `price_kind=synthetic`, `availability=synthetic_not_live`, `booking_created_at_supplier=false`. Это не подтверждение аэропорта, времени стыковки, реальной машины или наличия мест.

Конечный профиль: 400 RUB за каждого пассажира; при явно заданном поддержанном животном — дополнительная синтетическая строка 1000 RUB за животное, до20кг. Четыре места на синтетический автомобиль, число автомобилей округляется вверх; группа ограничена существующим engineering bound10 человек. Итог — целая сумма в RUB minor units, без скрытых сборов внутри синтетического правила. Это не рыночная оценка стоимости местного такси.

Идентичность включает trip/version, stay ID, place ID/version/hash, страну, обе гостиничные даты, путешественников и состав цены. Совпадающее название города в другой стране не использует российские DEMO-отели или перелёты. `assemble_plan` принимает только точный снимок этого конечного каталога; подмена даты, страны, вместимости, пассажиров, цены или происхождения отклоняется. Собственные DEMO ID/provider/catalogue нельзя переименовать в SANDBOX/LIVE-предложение с помощью поддельных supplier-флагов.

Все суммы синтетического трансфера включены в общий бюджет. Для отличающейся валюты требуется существующий reference FX. Неизвестные обязательные критерии и реальные supplier fees не удовлетворяются DEMO-трансфером. `MIXED` и `ready_for_simulated_checkout=true` разрешают только имитированное оформление; `ready_for_real_booking=false` остаётся неизменным.

Путь preview не обойдён: сначала `validate_quote`, затем refresh каждого внешнего предложения и `reprice_plan` для DEMO, повторная сборка, проверка снимков/бюджета и только новая quote. Изменённая source policy создаёт новую ревизию и отзывает прежнее согласие. Повтор simulated confirm возвращает один прежний заказ; внешняя бронь и оплата не выполняются.

Результат поиска отдельно сообщает `effective_transfer_demo_fallback`. Общее `effective_demo_fallback=false` у мировой географии сохраняется: отели и перелёты этим правилом не подменяются.

Проверки: единый финальный относящийся набор — **188 PASS / 0 skip, 6.94с**, включая3 API/PostgreSQL сценария на `otravel_test`: поиск→полный refresh→simulated confirm/repeat, отзыв quote при выключении fallback и отказ после утраты supplier fee evidence. Это controlled evidence. Первоначальные actual PARTIAL и6185-check checkpoint сохранены; новый actual-прогон выполняется отдельно оператором на зафиксированном snapshot.

Выбор «организую трансфер самостоятельно» в этой версии не добавлен: он потребовал бы отдельного сохранённого согласия на охват расходов. Сейчас неизвестная цена не удаляется из общего бюджета молча.
