# Подготовка сдачи O!Travel Agent

Сдаваемый репозиторий: [ostrovok-hackathon-2026/aegml](https://github.com/ostrovok-hackathon-2026/aegml). По техническим правилам финальный тег `submission` ставится на последнем коммите основной ветки. Сейчас тег не создаётся: сначала проверяем итоговую сборку и подключаем frontend.

Источники требований: [трек](https://docs.ostrovok.tech/s/0ee4d8b2-ae50-4dda-a2b5-112fcdb5398d), [технические правила](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc), [шифрование секретов](https://docs.ostrovok.tech/s/b9e6ec5e-5ad6-4091-9c85-a48eee9b21cc/doc/shifrovanie-sekretov-klyuchej-6Qhc4gJOPZ).

## Ключи для жюри

Организаторы требуют отдельные LLM-ключи только для жюри. Основной ключ разработчика не передаём. Перед шифрованием нужно создать выделенный ключ у выбранного провайдера, проверить бесплатный режим и явно записать провайдера/модель. Создание ciphertext само по себе не подтверждает работоспособность API или наличие квоты.

У используемых OpenRouter и Groq отдельный ключ не создаёт новую квоту аккаунта и не обнуляет расход разработчика. Перед передачей нужно проверить доступность выбранной модели и сохранить достаточный остаток для проверяющих; успешный `/health` этого не подтверждает.

Подготовьте отдельный `jury.env`. Не экспортируйте рабочий Master-файл целиком. Для локального helper используется `/home/aegml/projects/otravel/.local/submission/jury.env` в WSL AegML-Hackathon, права0600. Имена переменных должны совпадать с `.env.example`; ненужные значения остаются пустыми. Значения — UTF-8 без BOM, `NAME=value`, без кавычек и пробелов вокруг значения. `=` внутри Base64 допустим.

Числа, модели и другие несекретные defaults описаны в README/Compose. `.env.example` содержит только имена с пустыми значениями и пояснения, где получить ключ. Настройки БД внутри Compose задаются для сервиса `db`; не переносите в env для жюри локальные пути к WSL, чужой PostgreSQL или личные endpoint.

### Переносимая команда age

Установите [age из официального источника](https://github.com/FiloSottile/age) и проверьте `age --version`. В корне репозитория, для отдельного файла `.local/submission/jury.env`:

```text
age -r age1932fu7f70rwyfhaxflyfszz4gf6avxwc95wc0yjwm6zns9tspycqpgdnc0 -o secrets.env.age .local/submission/jury.env
```

Получатель скопирован из официальной инструкции Островка. SHA256 его ASCII-строки без перевода строки: `4c665c3e34c86188bfbad780f9b1c36c4de5e37be7e3b35a2cbca179bce6b1f8`.

Нужен обычный бинарный формат. Не добавляйте `-a`, не заменяйте `-o` на `>` и не используйте shell pipe: перенаправление в Windows PowerShell может испортить ciphertext. Если jury.env изменился, шифрование выполняется заново.

### Helper на машине разработчика

`scripts/encrypt_jury_secrets.py` использует только выделенный jury.env. По умолчанию он показывает состояние путей и не читает значения. Windows-команда обращается только к WSL AegML-Hackathon. Локальный age1.3.2 находится в `/home/aegml/tools/age-1.3.2`; архив и бинарник проверены по SHA официального release. Эта утилита не является зависимостью runtime-контейнера или обязательным инструментом жюри.

```powershell
py scripts/encrypt_jury_secrets.py --status
# Только после создания и проверки отдельных jury-only ключей:
py scripts/encrypt_jury_secrets.py --check
py scripts/encrypt_jury_secrets.py --encrypt --confirm-jury-only-keys
```

Значения не передаются через аргументы и не выводятся. Результат — корневой `secrets.env.age`; исходный jury.env не меняется. Повторная замена ciphertext требует явного `--replace`. Helper не коммитит, не отправляет файлы, не создаёт теги и не расшифровывает секреты организаторов.

Перед публикацией проверить, что `git ls-files .env` ничего не выводит, `.gitignore` содержит `.env`, а в сдаваемой ветке присутствуют `secrets.env.age` и пустой `.env.example`. Открытые ключи доступа не помещаем в Git, сообщения или видео. Если секрет ранее попал в историю, его необходимо перевыпустить; удаление файла из текущей ветки не удаляет старое значение из истории.

## Проверка поставки

- На чистом checkout выполнен `docker compose up --build` без дополнительных аргументов; открывается localhost8080, `/health` отвечает успешно. Все зависимые сервисы поднимаются в Docker.
- Уточнения, сохранение поездки, DEMO/ограниченный режим без LLM и перезапуск БД проверены на той же версии архива. Тестовый Docker project/volume отделён от рабочих данных.
- Провайдер, модель, ресурсы, переменные/defaults, создание БД и точки входа указаны в README. Готовность реальных источников подтверждается отдельно от управляемых тестов.
- Демо-видео записано, ссылка доступна без авторизации и проверена в инкогнито. Ссылка на развёрнутый сервис необязательна.
- Финальный frontend интегрирован и проверен. Сейчас используется временный `/debug`; frontend сокомандника подключается отдельно.
- После проверки финальный коммит находится в main официального репозитория и отмечен `submission`. Этот документ не создаёт тег автоматически.

Пока не закрыто: отдельные jury-only ключи, реальное шифрование и отправка ciphertext, публичное видео, финальная интеграция frontend. Не отмечайте эти пункты выполненными по одному существованию helper или успешному DEMO.
