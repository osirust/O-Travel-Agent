# Сравнение поисковых цен продавцов

Обычный поиск SerpApi возвращает список отелей. Для выбранного отеля доступен отдельный явный запрос деталей через существующий endpoint. Он расходует один поисковый запрос SerpApi; автоматической загрузки деталей всех отелей нет.

```http
POST /api/v1/sessions/{session_id}/live/search
Authorization: Bearer <session_token>
Content-Type: application/json
```

```json
{
  "client_message_id": "hotel-sellers-1",
  "expected_version": 3,
  "kind": "hotels",
  "provider": "serpapi",
  "request": {
    "property_token": "<token из details.provider_data.property_token выбранного предложения>",
    "checkin": "2026-11-10",
    "checkout": "2026-11-13",
    "currency": "RUB",
    "occupancies": [{"adults": 1, "children": []}]
  }
}
```

Ответ `202` содержит запуск; результат читается через `GET /api/v1/runs/{run_id}`. В полном HTTP-ответе предложения находятся в `run.result.result.live_offers`, а сравнение — в `run.result.result.live_offers[i].details.supplier_comparison`. Существующие session ownership, версии, журнал и квота сохраняются. API-ключ поставщика остаётся на сервере.

Первоначально детали поддерживают один номер для одного взрослого без детей. Несколько номеров и детские тарифы этой интеграцией пока не подтверждены. Для запроса деталей `q` не нужен: используется `property_token`. URL вместо токена не принимается. Ответ должен подтвердить тот же отель, даты, валюту и состав запроса.

## Дополнительное поле для frontend

У предложения необязательное поле `details.supplier_comparison`. Сериализатор должен сохранять его вложенную структуру; старые предложения этого поля не имеют.

- `seller_names`, `seller_count`, `seller_summaries` — названия продавцов из ответа и число подходящих ставок. Название агрегатора не заменяет название продавца.
- `comparison_groups` — группы по конкретному property token, датам, валюте и явно указанному числу гостей. В `rates` входят только комнатные тарифы с совпадающим `num_guests`; вместимость номера и сводная цена продавца этого не подтверждают.
- `rates` содержат сумму за всё проживание, название номера, сведения о кроватях, явный `breakfast_included`, условия отмены, раскрытые inclusions и `missing_evidence`. `null` означает неизвестное; оно не означает отсутствие услуги.
- `price_scope=source_reported_stay_total_after_taxes_fees` указывает поле поискового источника. Окончательные обязательные сборы и условия покупки не подтверждены.
- Дата отмены сохраняется текстом. Например, `Nov 2 / 11:59 PM` без года и часового пояса не становится проверенным ISO-дедлайном.
- `excluded` показывает неподходящее число гостей, отсутствие полной цены и усечение. В ответе не более 64 подходящих ставок; `matching_rate_limit_reached` сообщает о пределе.

У всех таких предложений источник `LIVE_INDICATIVE`, `allocation_verified=false`, `availability_verified=false`, `ready_for_real_booking=false`. Сравнение содержит `equivalent=false`, `supplier_bookable=false`: одинаковость физических номеров, условий и право на условные цены не доказаны одним названием.

Сумма внешнего предложения берётся из **первого раскрытого комнатного тарифа на запрошенное число гостей**. Политика выбора записана в `reference_selection_policy`. Она не обещает самый дешёвый или эквивалентный вариант. Например, сводную цену для двух или трёх гостей нельзя подписывать как цену для одного гостя. Если подходящего полного итога нет, сервер возвращает `NO_MATCHES`, сохраняя поездку.

Существующий reprice обновляет поисковую выдачу этого property token и остаётся `search_refresh_only`. Смена опорного тарифа отмечается `details.comparison_reference_changed`; это обновление справочной витрины, а не подтверждение прежнего выбранного номера. Реальные бронирования не создаются.

## Проверка

Два фактических запроса SerpApi 27 октября вернули один и тот же отель FIVE Jumeirah Village Hotel в Дубае, 12 названий продавцов и шесть комнатных ставок с явным `num_guests=1`. Условия и сведения о кроватях различались. [Результат](verification/serp-supplier-comparison-20261027.json) сохраняет ограничения; `HARNESS-001` по полной эквивалентности поставщиков остаётся OPEN.

Тестовая фикстура `fixtures/regression/serp-hotel-details-20261027.json` содержит проекцию двух настоящих ответов и SHA исходных private JSON. API-ключи, ссылки переходов, изображения и исходный property token исключены. Проверки адаптера используют `MockTransport`, не расходуют квоту и не квалифицируют новый запуск в Native.

Документация поставщика: [Google Hotels](https://serpapi.com/google-hotels-api), [Property Details](https://serpapi.com/google-hotels-property-details).
